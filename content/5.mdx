주소창에 주소를 입력하면 브라우저는 HTML 글자를 받아 화면에 그립니다. 그 사이에 어떤 단계를 거치는지 알면, 페이지가 왜 늦게 뜨는지와 어떤 CSS가 화면을 느리게 만드는지 이해할 수 있습니다.

## 1. 전체 흐름

```txt
HTML  →  DOM   ─┐
                ├→  렌더 트리  →  레이아웃  →  페인트  →  합성
CSS   →  CSSOM ─┘
```

브라우저는 HTML과 CSS를 각각 읽어 나무 모양의 구조 두 개를 만들고, 둘을 합친 뒤 위치를 계산하고, 칠하고, 겹쳐서 화면에 내보냅니다.

## 2. 파싱: DOM과 CSSOM, 그리고 막히는 지점

브라우저는 HTML을 위에서부터 읽으며 태그를 부모와 자식 관계의 나무 모양으로 정리합니다. 이것이 DOM입니다. CSS도 같은 방식으로 읽어 어떤 요소에 어떤 스타일이 붙는지 정리하는데, 이것을 CSSOM이라고 합니다.

이때 두 가지가 화면을 늦춥니다. 먼저 CSS는 다 읽기 전까지 화면을 그리지 않습니다. 스타일이 없는 화면이 잠깐 보이는 것을 막기 위해서입니다. 그리고 `defer`나 `async`가 없는 `script`를 만나면 HTML 읽기를 멈추고, 스크립트를 내려받아 실행한 뒤에야 다시 읽습니다.

```html
<script src="app.js"></script>        <!-- HTML 읽기를 멈춘다 -->
<script defer src="app.js"></script>  <!-- 끝까지 읽은 뒤 순서대로 실행 -->
<script async src="ad.js"></script>   <!-- 받는 대로 실행, 순서 보장 없음 -->
```

그래서 페이지의 동작을 맡는 스크립트에는 보통 `defer`를 붙이고, 다른 코드와 상관없는 광고나 분석 스크립트에는 `async`를 붙입니다.

## 3. 렌더 트리

DOM과 CSSOM을 합쳐 실제로 화면에 보일 요소만 모은 것이 렌더 트리입니다. `display: none`인 요소는 화면에 자리를 차지하지 않으므로 렌더 트리에서 빠집니다. 반면 `visibility: hidden`인 요소는 보이지 않을 뿐 자리는 차지하므로 남습니다.

## 4. 레이아웃, 페인트, 합성

레이아웃 단계에서는 각 요소의 위치와 크기를 계산합니다. 페인트 단계에서는 글자, 색, 테두리, 그림자를 픽셀로 칠합니다. 마지막 합성 단계에서는 따로 칠한 층(레이어)을 순서대로 겹쳐 화면에 내보냅니다.

```css
.box {
  width: 300px; /* 바뀌면 레이아웃부터 다시 */
  color: red; /* 바뀌면 페인트부터 다시 */
  transform: translateX(20px); /* 바뀌면 대부분 합성만 다시 */
}
```

`width`처럼 크기나 위치를 바꾸는 속성은 레이아웃부터 다시 계산해서 가장 비쌉니다. 색만 바꾸면 페인트부터 다시 하고, `transform`과 `opacity`는 대부분 합성 단계만 다시 하므로 애니메이션에 쓰기 좋습니다.

## 5. 자바스크립트로 레이아웃을 여러 번 일으키지 않기

스타일을 바꾼 직후에 `offsetWidth`나 `getBoundingClientRect()`처럼 크기를 읽으면, 브라우저는 정확한 값을 주려고 레이아웃을 그 자리에서 다시 계산합니다. 반복문 안에서 쓰기와 읽기를 번갈아 하면 레이아웃이 매번 일어나 화면이 버벅입니다.

```js
// 나쁜 예: 읽기와 쓰기를 번갈아 해서 레이아웃이 반복된다
boxes.forEach((box) => {
  box.style.width = `${container.offsetWidth / 2}px`;
});

// 좋은 예: 먼저 한 번 읽고, 그다음에 모아서 쓴다
const half = container.offsetWidth / 2;
boxes.forEach((box) => {
  box.style.width = `${half}px`;
});
```

> 움직임은 `transform`으로 만들고, 크기를 읽는 일은 쓰기 전에 모아서 합니다.
