주소창에 주소를 입력하면 브라우저는 HTML 글자를 받아 화면에 그립니다. 그 사이에 어떤 단계를 거치는지 알면, 어떤 CSS가 화면을 느리게 만드는지도 이해할 수 있습니다.

## 1. 전체 흐름

```txt
HTML  →  DOM   ─┐
                ├→  렌더 트리  →  레이아웃  →  페인트  →  합성
CSS   →  CSSOM ─┘
```

## 2. DOM과 CSSOM 만들기

브라우저는 HTML을 위에서부터 읽으며 태그를 부모와 자식 관계의 나무 모양으로 정리합니다. 이것이 DOM입니다. CSS도 같은 방식으로 읽어 어떤 요소에 어떤 스타일이 붙는지 정리하는데, 이것을 CSSOM이라고 합니다.

## 3. 렌더 트리

DOM과 CSSOM을 합쳐 실제로 화면에 보일 요소만 모은 것이 렌더 트리입니다. `display: none`인 요소는 화면에 자리를 차지하지 않으므로 렌더 트리에서 빠집니다. 반면 `visibility: hidden`인 요소는 보이지 않을 뿐 자리는 차지하므로 남습니다.

## 4. 레이아웃, 페인트, 합성

레이아웃 단계에서는 각 요소의 위치와 크기를 계산합니다. 페인트 단계에서는 글자, 색, 테두리, 그림자를 픽셀로 칠합니다. 마지막 합성 단계에서는 따로 칠한 층(레이어)을 순서대로 겹쳐 화면에 내보냅니다.

```css
.box {
  width: 300px; /* 바뀌면 레이아웃부터 다시 */
  color: red; /* 바뀌면 페인트부터 다시 */
  transform: translateX(20px); /* 바뀌면 대부분 합성만 다시 */
}
```

`width`처럼 크기나 위치를 바꾸는 속성은 레이아웃부터 다시 계산해서 가장 비쌉니다. 색만 바꾸면 페인트부터 다시 하고, `transform`과 `opacity`는 대부분 합성 단계만 다시 하므로 애니메이션에 쓰기 좋습니다.

> 움직임은 `transform`으로 만들고, 크기 계산은 꼭 필요할 때만 일으킵니다.
