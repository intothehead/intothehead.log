프론트엔드에서 API를 처음 연결하면 콘솔에 "blocked by CORS policy"라는 빨간 글자를 자주 만납니다. 그런데 같은 주소를 Postman으로 부르면 잘 됩니다. 이 글에서는 CORS 에러가 왜 브라우저에서만 생기는지, 누가 무엇을 고쳐야 하는지 정리합니다.

## 1. 출처란 무엇일까

출처(origin)는 주소의 **프로토콜, 호스트, 포트** 세 가지를 합친 것입니다. 셋 중 하나라도 다르면 다른 출처입니다.

```txt
https://blog.com/posts         기준
https://blog.com/about         같은 출처 (경로만 다름)
http://blog.com/posts          다른 출처 (프로토콜이 다름)
https://api.blog.com/posts     다른 출처 (호스트가 다름)
http://localhost:3000 과 http://localhost:8080   다른 출처 (포트가 다름)
```

개발할 때 프론트는 3000번, 백엔드는 8080번 포트에서 띄우는 경우가 많아서, 같은 컴퓨터인데도 다른 출처가 됩니다.

## 2. 같은 출처 정책: 브라우저가 지키는 규칙

브라우저는 기본적으로 다른 출처에서 받은 응답을 자바스크립트가 읽지 못하게 막습니다. 이것을 같은 출처 정책이라고 합니다. 만약 이 규칙이 없다면, 내가 방문한 나쁜 사이트의 자바스크립트가 내 로그인 정보를 실어 은행 사이트에 요청을 보내고 그 응답까지 읽어 갈 수 있습니다.

이 규칙은 **브라우저가 사용자를 지키려고** 하는 것입니다. 그래서 Postman이나 서버끼리 주고받는 요청에는 CORS가 없습니다. 그리고 많은 경우 요청은 서버에 실제로 도착하고 응답도 돌아오지만, 브라우저가 그 응답을 자바스크립트에 넘겨주지 않는 것입니다.

## 3. 서버가 허락해 주는 방법

CORS(Cross-Origin Resource Sharing)는 서버가 "이 출처에는 읽어도 된다"고 허락하는 방법입니다. 브라우저는 요청에 `Origin` 헤더를 붙여 보내고, 서버가 응답에 허락하는 출처를 적어 주면 그때 응답을 넘겨줍니다.

```txt
요청 헤더
Origin: http://localhost:3000

응답 헤더
Access-Control-Allow-Origin: http://localhost:3000
```

그래서 CORS 에러를 고치는 곳은 프론트가 아니라 **서버**입니다. 쿠키를 함께 보내야 한다면 프론트에서 `credentials: "include"`를 주고, 서버는 `Access-Control-Allow-Credentials: true`를 보내야 합니다. 이때는 허락하는 출처를 `*`로 쓸 수 없고 정확한 주소를 적어야 합니다.

## 4. 프리플라이트: 보내기 전에 먼저 묻기

`PUT`이나 `DELETE` 요청, `Content-Type: application/json`, `Authorization` 같은 헤더가 붙은 요청은 서버의 데이터를 바꿀 수 있어서 더 조심합니다. 브라우저는 진짜 요청을 보내기 전에 `OPTIONS` 요청으로 먼저 허락을 구하는데, 이것을 프리플라이트라고 합니다.

```txt
OPTIONS /posts
Origin: http://localhost:3000
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: content-type

204 No Content
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST, PUT
Access-Control-Allow-Headers: content-type
```

서버가 이 질문에 제대로 답하지 않으면 진짜 요청은 보내지지도 않습니다. 개발자 도구의 Network 탭에서 `OPTIONS` 요청이 실패했는지 보면 원인을 빨리 찾을 수 있습니다. 개발 중에는 Next.js의 rewrites로 요청을 같은 출처처럼 보이게 우회할 수도 있지만, 실제 서비스에서는 서버가 허락하도록 설정하는 것이 맞습니다.

> CORS 에러는 브라우저가 사용자를 지키느라 내는 것이고, 고치는 열쇠는 서버가 쥐고 있습니다.
