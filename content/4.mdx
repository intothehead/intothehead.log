TypeScript를 쓰면서 `Promise<{ id: string }>`나 `useState<string>`처럼 꺾쇠가 붙은 타입을 자주 봤지만, 처음에는 그냥 외워서 썼습니다. 이 글에서는 제네릭이 무엇인지 직접 만든 작은 함수로 하나씩 풀어 봅니다.

## 1. 타입을 정하지 못하는 함수

배열의 첫 번째 값을 꺼내는 함수를 만든다고 해 봅니다. 숫자 배열에도, 글자 배열에도 쓰고 싶다면 타입을 무엇으로 적어야 할까요?

```ts
function first(items: any[]) {
  return items[0];
}

const value = first(["React", "Next.js"]); // value의 타입: any
```

`any`를 쓰면 어떤 배열이든 넣을 수 있지만, 꺼낸 값이 무엇인지 TypeScript가 알 수 없게 됩니다. 오타가 나도 빨간 줄이 생기지 않습니다.

## 2. 타입을 매개변수처럼 받기

제네릭은 함수가 값을 매개변수로 받듯이, 타입도 매개변수로 받는 방법입니다. 함수 이름 뒤 꺾쇠 안의 `T`가 타입의 빈칸입니다.

```ts
function first<T>(items: T[]): T | undefined {
  return items[0];
}

const tag = first(["React", "Next.js"]); // string | undefined
const id = first([1, 2, 3]); // number | undefined
```

함수를 부를 때 넣은 배열을 보고 TypeScript가 `T`를 알아서 채웁니다. 빈 배열일 수도 있으니 돌려주는 타입에 `undefined`를 함께 적었습니다.

## 3. 이미 쓰고 있던 제네릭

알고 보니 제네릭은 이미 자주 쓰고 있었습니다.

```ts
const [selectedTag, setSelectedTag] = useState<string>("전체");

type PostDetailProps = {
  params: Promise<{ id: string }>;
};
```

`useState<string>`은 "이 state에는 글자가 들어간다", `Promise<{ id: string }>`는 "열면 id가 든 객체가 나오는 상자"라는 뜻입니다. 둘 다 빈칸 `T`에 실제 타입을 넣어 쓴 것입니다.

> 제네릭은 타입 자리에 남겨 둔 빈칸이고, 쓰는 순간에 채워집니다.
