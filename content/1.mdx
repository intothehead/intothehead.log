불필요한 리렌더링을 줄이려고 `memo`와 `useCallback`을 습관처럼 붙이는 경우가 많습니다. 하지만 두 도구는 쓸 곳과 쓰지 않아도 될 곳이 분명합니다. 이 글에서는 리렌더링이 왜 생기는지부터 확인하고, 두 도구가 실제로 도움이 되는 상황을 구분해 봅니다.

## 1. 리렌더링은 언제 일어날까

컴포넌트는 자기 state가 바뀌거나, 부모 컴포넌트가 다시 그려질 때 함께 다시 그려집니다. 두 번째 경우는 자식이 받는 props가 그대로여도 일어납니다.

```tsx
function Parent() {
  const [count, setCount] = useState(0);

  return (
    <>
      <button onClick={() => setCount(count + 1)}>{count}</button>
      <Child title="고정된 제목" />
    </>
  );
}
```

버튼을 누르면 `count`만 바뀌지만, `Parent`가 다시 그려지면서 `Child`도 함께 다시 그려집니다. 대부분은 이 정도 리렌더링이 문제가 되지 않습니다. React는 실제 화면(DOM)에서 바뀐 부분만 고치기 때문입니다.

## 2. memo로 같은 props면 건너뛰기

`Child`가 무거운 계산을 하거나 긴 목록을 그린다면 매번 다시 그리는 비용이 커집니다. 이럴 때 `memo`로 감싸면, props가 이전과 같을 때 다시 그리지 않고 지난 결과를 그대로 씁니다.

```tsx
import { memo } from "react";

const Child = memo(function Child({ title }: { title: string }) {
  return <h2>{title}</h2>;
});
```

## 3. 함수 props에는 useCallback

`memo`는 새 props를 이전 props와 비교합니다. 그런데 컴포넌트 안에서 만든 함수는 렌더링할 때마다 새로 만들어지므로, 내용이 같아도 다른 값으로 판단됩니다. 그러면 `memo`를 붙여도 자식은 계속 다시 그려집니다.

```tsx
const handleClick = useCallback(() => {
  console.log("clicked");
}, []);

return <MemoButton onClick={handleClick} />;
```

`useCallback`은 의존성 배열의 값이 바뀌지 않는 한 같은 함수를 돌려줍니다. 그래서 `memo`로 감싼 자식에게 함수를 넘길 때 짝으로 씁니다.

## 4. 쓰지 않아도 되는 경우

가벼운 컴포넌트라면 props를 비교하는 비용이 다시 그리는 비용보다 클 수 있습니다. `memo`로 감싸지 않은 자식에게 넘기는 함수에 `useCallback`을 붙이는 것도 효과가 없습니다. 먼저 React DevTools의 Profiler로 오래 걸리는 컴포넌트를 찾고, 그곳에만 적용하는 것이 좋습니다.

이 블로그처럼 React Compiler를 켜 두면, 컴파일러가 빌드할 때 필요한 곳에 메모이제이션을 자동으로 넣어 줍니다. 그래서 `memo`와 `useCallback`을 직접 쓸 일이 크게 줄어듭니다.
