면접에서 자주 나오는 질문 중 하나가 "클로저가 무엇인가요?"입니다. 정의만 외우면 금방 잊어버리는데, React를 쓰다 보면 클로저 때문에 생기는 버그를 직접 만나게 됩니다. 이 글에서는 클로저를 작은 예제로 확인하고 React의 "오래된 값" 문제까지 연결해 봅니다.

## 1. 함수는 만들어진 곳의 변수를 기억한다

```js
function makeCounter() {
  let count = 0;

  return function () {
    count += 1;
    return count;
  };
}

const counter = makeCounter();
counter(); // 1
counter(); // 2
```

`makeCounter`는 이미 실행이 끝났는데도 `count`가 사라지지 않고 계속 늘어납니다. 안쪽 함수가 자기가 만들어진 자리의 변수 `count`를 붙잡고 있기 때문입니다. 이렇게 함수가 바깥 변수를 기억하는 것을 클로저라고 합니다.

## 2. 클로저로 값 숨기기

`count`는 `makeCounter` 밖에서 직접 바꿀 수 없습니다. 오직 돌려받은 함수로만 늘릴 수 있습니다. 그래서 클로저는 외부에서 함부로 건드리면 안 되는 값을 숨기는 데 씁니다.

```js
const a = makeCounter();
const b = makeCounter();

a(); // 1
a(); // 2
b(); // 1 — b는 자기만의 count를 따로 기억한다
```

`makeCounter`를 부를 때마다 새로운 `count`가 만들어지고, 각 함수는 자기 것만 기억합니다.

## 3. 반복문에서 만나는 클로저: var와 let

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// 0, 1, 2
```

`var`로 만든 `i`는 반복 전체에서 하나뿐이라, 세 함수가 모두 같은 `i`를 기억합니다. 함수가 실행될 때는 반복이 끝나 `i`가 3입니다. `let`은 반복할 때마다 새 `j`를 만들어서, 각 함수가 그때의 값을 따로 기억합니다.

## 4. React에서 만나는 클로저: 오래된 값

```tsx
function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      setCount(count + 1); // 처음 렌더링의 count(0)를 계속 기억한다
    }, 1000);
    return () => clearInterval(id);
  }, []);

  return <p>{count}</p>;
}
```

1초마다 늘어날 것 같지만 화면은 1에서 멈춥니다. `useEffect`가 처음 한 번만 실행되면서, 그 안의 함수가 첫 렌더링의 `count`인 0을 기억하기 때문입니다. 그래서 매번 `0 + 1`만 계산합니다.

```tsx
setCount((prev) => prev + 1);
```

이렇게 함수를 넘기면 React가 그때의 최신 값을 `prev`로 넣어 주므로, 오래된 값을 기억하는 문제가 사라집니다.

> 함수는 실행되는 곳이 아니라 만들어진 곳의 변수를 기억합니다.
