자바스크립트는 한 번에 한 가지 일만 하는 싱글 스레드 언어입니다. 그런데 서버 응답을 기다리는 동안에도 화면은 멈추지 않고, 버튼도 눌립니다. 이 글에서는 그 비밀인 이벤트 루프를 콜 스택과 두 가지 큐로 나눠 정리합니다.

## 1. 콜 스택: 한 번에 하나씩

함수를 부르면 콜 스택에 쌓이고, 끝나면 빠집니다. 콜 스택에 무언가 남아 있는 동안 자바스크립트는 다른 일을 하지 못합니다.

```js
function heavy() {
  const end = Date.now() + 3000;
  while (Date.now() < end) {} // 3초 동안 콜 스택을 차지한다
}

heavy(); // 이 3초 동안은 버튼을 눌러도 반응이 없다
```

화면을 그리는 일도 같은 스레드에서 하기 때문에, 오래 걸리는 계산 하나가 페이지 전체를 멈추게 합니다.

## 2. 기다리는 일은 브라우저에 맡긴다

`setTimeout`, `fetch`, 클릭 이벤트처럼 기다려야 하는 일은 브라우저가 대신 맡습니다. 기다림이 끝나면 실행할 함수(콜백)를 큐에 넣어 두고, 이벤트 루프가 콜 스택이 빌 때마다 큐에서 하나씩 꺼내 실행합니다.

```txt
콜 스택  ←  이벤트 루프  ←  마이크로태스크 큐 (Promise의 then, await 뒤)
                         ←  태스크 큐 (setTimeout, 이벤트)
```

큐는 두 종류입니다. 이벤트 루프는 태스크 하나를 처리할 때마다 마이크로태스크 큐를 **끝까지 비운 뒤에** 다음 태스크로 넘어갑니다. 그래서 Promise 쪽이 항상 먼저입니다.

## 3. 실행 순서 맞혀 보기

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");

// 출력: 1, 4, 3, 2
```

먼저 콜 스택에 있는 일반 코드가 끝까지 실행되어 1과 4가 나옵니다. 그다음 마이크로태스크 큐의 3이 나오고, 마지막으로 태스크 큐의 2가 나옵니다. `setTimeout`에 0을 줘도 "바로"가 아니라 "지금 하던 일과 Promise가 모두 끝난 뒤"에 실행됩니다.

## 4. async/await도 같은 규칙을 따른다

`await` 뒤에 오는 코드는 마이크로태스크로 미뤄집니다. 그래서 함수 밖의 코드가 먼저 실행됩니다.

```js
async function load() {
  console.log("A");
  await null;
  console.log("B");
}

load();
console.log("C");

// 출력: A, C, B
```

이 규칙을 알면 "데이터를 받기도 전에 다음 줄이 실행되는" 버그를 이해할 수 있습니다. 그리고 화면을 오래 멈추게 하는 무거운 계산은 잘게 나눠 실행하거나 Web Worker처럼 다른 스레드로 옮겨야 한다는 것도 알 수 있습니다.

> setTimeout 0은 "지금 당장"이 아니라 "지금 하던 일과 Promise가 다 끝난 뒤"입니다.
