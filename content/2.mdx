블로그를 만들면서 Next.js App Router의 구조를 처음 제대로 익혔습니다. App Router에서는 폴더 구조가 곧 주소가 되고, 화면을 서버에서 먼저 그리는 것이 기본입니다. 이 글에서는 홈, 전체 글, 글 상세 세 페이지의 뼈대를 세우면서 알게 된 규칙을 정리합니다.

## 1. 폴더가 곧 주소

`app` 폴더 안에서 `page.tsx`가 있는 폴더 하나가 주소 하나가 됩니다. 폴더만 있고 `page.tsx`가 없으면 주소가 생기지 않습니다.

```txt
app/
├─ layout.tsx        모든 페이지를 감싸는 틀
├─ page.tsx          /
├─ not-found.tsx     없는 주소일 때 보여 줄 화면
└─ posts/
   ├─ page.tsx       /posts
   └─ [id]/
      └─ page.tsx    /posts/1, /posts/2 ...
```

`page.tsx`, `layout.tsx`, `not-found.tsx`처럼 Next.js가 이름으로 알아보는 파일이 정해져 있습니다. 반대로 `components`나 `data`처럼 `app` 밖에 둔 폴더는 주소가 되지 않으므로, 화면 조각과 자료를 나눠 두는 곳으로 씁니다.

## 2. 레이아웃은 이동해도 다시 그려지지 않는다

`app/layout.tsx`는 모든 페이지를 감쌉니다. 페이지 내용은 `children` 자리에 들어오므로, 헤더와 푸터를 여기에 한 번만 두면 모든 페이지에 나옵니다.

```tsx
export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html lang="ko">
      <body>
        <Header />
        {children}
        <Footer />
      </body>
    </html>
  );
}
```

페이지를 옮겨 다녀도 레이아웃은 다시 그려지지 않고 `children` 자리만 바뀝니다. 그래서 헤더 안의 테마 버튼 같은 부분은 이동할 때마다 처음부터 다시 만들어지지 않습니다.

## 3. 서버 컴포넌트가 기본, `"use client"`는 필요한 곳만

App Router의 컴포넌트는 기본적으로 서버에서 그려집니다. 서버 컴포넌트는 파일을 읽거나 데이터를 가져온 뒤 완성된 HTML을 보내므로, 브라우저로 가는 JavaScript가 줄어듭니다. 대신 `useState`나 `onClick`처럼 브라우저에서 움직여야 하는 코드는 쓸 수 없습니다.

```tsx
"use client";

export default function FilteredPostList({ posts }: FilteredPostListProps) {
  const [selectedTag, setSelectedTag] = useState("전체");
  // 버튼을 누를 때마다 목록을 거른다
}
```

이 블로그에서는 태그 필터처럼 누르면 바뀌는 부분만 파일 맨 위에 `"use client"`를 적어 클라이언트 컴포넌트로 만들었습니다. 글 목록은 서버 페이지가 파일에서 읽어 props로 내려줍니다. 클라이언트 영역을 작게 둘수록 브라우저로 보내는 코드가 적어집니다.

## 4. 대괄호 폴더로 글 상세 만들기

글마다 폴더를 만들 수는 없으니, 폴더 이름을 대괄호로 감싸 주소의 빈칸을 만듭니다. `app/posts/[id]/page.tsx` 하나가 `/posts/1`과 `/posts/2`를 모두 받습니다. 빈칸에 들어온 값은 `params`로 받는데, Next.js 15부터는 바로 쓸 수 있는 값이 아니라 Promise라서 `await`로 꺼냅니다.

```tsx
export async function generateStaticParams() {
  const posts = await getPosts();
  return posts.map((post) => ({ id: String(post.id) }));
}

export default async function PostDetail({ params }: PostDetailProps) {
  const { id } = await params;
  const posts = await getPosts();
  const post = posts.find((item) => String(item.id) === id);

  if (!post) {
    notFound();
  }

  return <h1>{post.title}</h1>;
}
```

`generateStaticParams`는 어떤 번호가 올 수 있는지 미리 알려 주는 함수입니다. 알려 준 글들은 빌드할 때 미리 만들어 두므로 처음 열 때도 빠릅니다. 목록에 없는 번호가 들어오면 `notFound()`가 `not-found.tsx` 화면을 보여 줍니다.

> 주소를 먼저 폴더로 그려 보면, 만들어야 할 페이지와 나눠야 할 컴포넌트가 한눈에 보입니다.
