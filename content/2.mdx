블로그를 만들면서 Next.js App Router의 폴더 구조를 처음 제대로 익혔습니다. App Router에서는 폴더가 곧 주소가 되고, 레이아웃이 여러 페이지를 감쌉니다. 이 글에서는 블로그의 홈, 전체 글, 글 상세 페이지 뼈대를 세우는 과정을 정리합니다.

## 1. 폴더가 곧 주소

`app` 폴더 안에서 `page.tsx`가 있는 폴더 하나가 주소 하나가 됩니다.

```txt
app/
├─ layout.tsx        모든 페이지를 감싸는 틀
├─ page.tsx          /
└─ posts/
   ├─ page.tsx       /posts
   └─ [id]/
      └─ page.tsx    /posts/1, /posts/2 ...
```

`components`나 `data`처럼 `app` 밖에 있는 폴더는 주소가 되지 않습니다. 화면 조각과 자료를 나눠 두는 곳으로 씁니다.

## 2. 레이아웃으로 헤더와 푸터 한 번만 쓰기

`app/layout.tsx`는 모든 페이지를 감쌉니다. 페이지 내용은 `children` 자리에 들어오므로, 헤더와 푸터를 여기에 한 번만 두면 모든 페이지에 나옵니다.

```tsx
export default function RootLayout({ children }: LayoutProps<"/">) {
  return (
    <html lang="ko">
      <body>
        <Header />
        {children}
        <Footer />
      </body>
    </html>
  );
}
```

## 3. 대괄호 폴더로 글 상세 만들기

글마다 폴더를 만들 수는 없으니, 폴더 이름을 대괄호로 감싸 주소의 빈칸을 만듭니다. `app/posts/[id]/page.tsx` 하나가 `/posts/1`과 `/posts/2`를 모두 받습니다. 빈칸에 들어온 값은 `params`로 받는데, 바로 쓸 수 있는 값이 아니라 Promise라서 `await`로 꺼냅니다.

```tsx
export function generateStaticParams() {
  return posts.map((post) => ({ id: String(post.id) }));
}

export default async function PostDetail({ params }: PostDetailProps) {
  const { id } = await params;
  const post = posts.find((item) => String(item.id) === id);

  if (!post) {
    notFound();
  }

  return <h1>{post.title}</h1>;
}
```

`generateStaticParams`는 어떤 번호가 올 수 있는지 미리 알려 주는 함수입니다. 목록에 없는 번호가 들어오면 `notFound()`로 404 화면을 보여 줍니다.

> 주소를 먼저 폴더로 그려 보면, 만들어야 할 페이지가 한눈에 보입니다.
